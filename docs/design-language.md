# Bahar Design System — Meta-derived, Bahar-colored

> مرجع ساختاری و بصری: `VoltAgent/awesome-design-md/design-md/meta/DESIGN.md`.
> این سند اقتباس کاربردی برای یک سامانهٔ مدیریت مدرسه است؛ کپیِ صفحهٔ فروش سخت‌افزار Meta نیست.
> **قاعدهٔ غیرقابل‌مذاکره: تمام رنگ‌های فعلی بهار حفظ می‌شوند؛ هیچ رنگ برند Meta وارد محصول نمی‌شود.**

## 1. اصول هویت بصری

- زبان بصری Meta: سطوح روشن و تمیز، تایپوگرافی با سلسله‌مراتب واضح، فضای تنفس کافی، گوشه‌های نرم و بزرگ، کنترل‌های capsule و مرزبندی‌های ظریف.
- حس محصول: دقیق، قابل اعتماد، آرام و حرفه‌ای؛ مناسب استفادهٔ روزانه و طولانی‌مدت کارکنان مدرسه.
- محتوای عملیاتی بر تزئینات اولویت دارد. الگوی عکس تمام‌عرض و hero تجاری Meta برای داشبورد، فرم، جدول و گزارش به کارت‌های داده‌محور و ماژولار تبدیل می‌شود.
- تراکم اطلاعات در صفحات جدولی حفظ می‌شود؛ فضای سفید نباید باعث پنهان‌شدن اطلاعات یا اسکرول غیرضروری شود.
- ساختار RTL فارسی، چندزبانه‌بودن، تقویم جلالی و ارقام فارسی دست‌نخورده می‌مانند.

## 2. رنگ‌ها — فقط پالت بهار

هیچ توکن رنگی تازه‌ای برای برند اضافه نشود. تمام رنگ‌ها از توکن‌های فعلی پروژه و تم‌های موجود خوانده شوند.

| نقش | توکن فعلی | مقدار |
|---|---|---|
| برند اصلی | `--spring` | `#00825E` |
| برند تیره | `--spring-deep` | `#005A42` |
| برند روشن | `--spring-soft` | `#7FD6B8` |
| سطح انتخاب | `--spring-tint` | `#E8F0EC` |
| تاکید ثانویه | `--blossom` | `#E5548B` |
| متن اصلی | `--ink` | `#0A1E17` |
| متن فرعی | `--steel` | `#5B6B66` |
| متن کم‌رنگ | `--stone` | `#8A9691` |
| پس‌زمینه | `--background` | `#FFFFFF` |
| سطح خنثی | `--cloud` | `#F2F4F3` |
| جداکننده | `--hairline-soft` | `#DFE3E0` |
| خطا | `--destructive` | توکن موجود |
| هشدار | `--amber` | توکن موجود |

- رنگ آبی `#0064E0` و سایر رنگ‌های اختصاصی Meta ممنوع‌اند.
- رنگ‌های وضعیت موجود (موفقیت، هشدار، خطا و اطلاعات) فقط برای معنای وضعیت استفاده شوند؛ نه تزئین.
- صورتی شکوفه حداکثر برای تاکید ثانویه و نقاط کوچک باقی بماند.
- در تم تاریک، توکن‌های متناظر فعلی حفظ شوند؛ مقدارهای روشن/تیرهٔ جدید به‌صورت موردی اختراع نشوند.

## 3. تایپوگرافی

Meta در مرجع از Optimistic VF استفاده می‌کند؛ این فونت اختصاصی است و برای فارسیِ بهار جایگزین مستقیم مناسبی ندارد. بنابراین هندسه و سلسله‌مراتب Meta با فونت‌های موجود پیاده می‌شود:

- فارسی: Arad برای تیترها و Vazirmatn برای بدنه و کنترل‌ها.
- لاتین: Manrope از زنجیرهٔ فعلی پروژه.
- تیترها با وزن متوسط/نیمه‌ضخیم، نه ضخامت سنگین در همه‌جا.
- بدنهٔ فارسی با line-height خوانا؛ فاصله‌گذاری حروف فارسی صفر.
- سلسله‌مراتب محدود و ثابت: Display، H1، H2، H3، Body، Caption.
- متن دکمه و تب‌ها ۱۴px با وزن ۷۰۰؛ متن بدنه ۱۴–۱۶px؛ متن کمکی ۱۲px.
- هیچ فونت خارجی یا فونت جدیدی بدون نیاز واقعی به پروژه اضافه نشود.

## 4. هندسه و فاصله‌گذاری

| عنصر | قاعده |
|---|---|
| دکمهٔ اصلی/ثانویه | capsule کامل، ارتفاع لمس حداقل ۴۴px |
| تب‌ها و فیلترها | pill با حالت فعال واضح |
| کارت شاخص | شعاع ۳۲px |
| کارت استاندارد | شعاع ۲۴px |
| کارت فشرده | شعاع ۱۶px |
| ورودی‌ها | شعاع ۱۲–۱۶px، ارتفاع حداقل ۴۴px |
| فاصله‌ها | شبکهٔ ۴px؛ مقادیر پرتکرار ۸، ۱۲، ۱۶، ۲۴، ۳۲ |
| جداکننده | hairline کم‌رنگ، نه border ضخیم |
| سایه | محدود به سطوح شناور و مودال؛ از سایهٔ دائمی روی همهٔ کارت‌ها پرهیز شود |

- دکمه‌های مهم capsule و مشکی Meta نیستند؛ رنگ اصلی آن‌ها سبز بهار است.
- کارت‌های داده بدون عکس با سطح روشن و border ظریف ساخته شوند.
- کارت‌های کلیک‌پذیر hover ملایم داشته باشند؛ کارت‌های صرفاً اطلاعاتی نباید وانمود کنند قابل کلیک‌اند.

## 5. اجزای اصلی

### ناوبری
- دسکتاپ: سایدبار راست با گروه‌بندی واضح، امکان جمع‌شدن و نشانگر فعال capsule.
- موبایل: هدر فشرده و drawer/launcher سازگار با ساختار موجود؛ هیچ مسیر یا آیتمی حذف نمی‌شود.
- هدر محتوا: جست‌وجوی سراسری، اعلان‌ها و کنترل‌های زمینه‌ای در یک ردیف مرتب.

### دکمه‌ها
- Primary: سبز بهار، capsule، متن خوانا.
- Secondary: زمینهٔ شفاف/خنثی با hairline.
- Tertiary/Ghost: بدون سطح دائمی، hover خنثی.
- Destructive: فقط برای عملیات مخرب.
- حالت‌های hover، pressed، focus-visible، disabled و loading باید تعریف شوند.

### کارت‌ها
- کارت شاخص: برای یک KPI یا پیام مهم، نه برای هر قطعهٔ محتوا.
- کارت استاندارد: برای گروه‌های مرتبط داده و عملیات.
- کارت فشرده: برای جدول‌ها، ردیف‌ها و پنل‌های متراکم.
- سلسله‌مراتب عنوان، توضیح و داده در همهٔ کارت‌ها یکسان باشد.

### فرم‌ها و جدول‌ها
- برچسب بالای ورودی، توضیح/خطا زیر آن.
- فوکوس سبز با حلقهٔ قابل مشاهده.
- جدول‌ها تراکم کنترل‌شده، ردیف‌های قابل اسکن، سربرگ واضح و فیلترهای pill داشته باشند.
- در موبایل، جدول به کارت/ردیف قابل پیمایش تبدیل شود؛ ستون یا عملیات حذف نشود.

## 6. حرکت و تعامل — الهام از Scrolltide

حرکت باید اطلاعات را آشکار کند و حس پاسخ‌گویی بدهد؛ نه اینکه کار اداری را کند کند.

- Scroll progress باریک و چسبیده به لبهٔ بالای viewport.
- ورود بخش‌ها با opacity + translate کوتاه و stagger بر اساس اهمیت.
- Scroll reveal فقط یک‌بار یا در ورود مجدد کنترل‌شده؛ از انیمیشن مداوم هنگام اسکرول جدول‌های طولانی پرهیز شود.
- انتقال صفحه: fade کوتاه + جابه‌جایی جزئی؛ حفظ scroll position و جلوگیری از layout shift.
- نمودارها: ترسیم تدریجی مسیر/میله و شمارندهٔ عددی با مدت کوتاه.
- hover/tap: scale بسیار کم و بازخورد سریع.
- parallax و عمق 3D فقط در سطوح خلاصه/معرفی و در صورت سودمندی؛ در فرم، جدول، تقویم، ویرایشگر و ابزارهای روزمره ممنوع.
- shader و پس‌زمینهٔ GPU فقط برای صفحات معرفی/ورود، نه داشبورد عملیاتی.
- ترجیح کاربر `prefers-reduced-motion` و تنظیمات دسترس‌پذیری پروژه همیشه رعایت شود.
- محتوای حیاتی نباید برای ظاهرشدن به اسکرول یا انیمیشن وابسته باشد.

## 7. واکنش‌گرایی و دسترس‌پذیری

- اولویت طراحی: ۳۶۰–۳۹۰px، سپس تبلت و دسکتاپ.
- هدف لمس حداقل ۴۴×۴۴px.
- کنتراست متن بدنه حداقل WCAG AA.
- فوکوس کیبورد مشخص؛ همهٔ کنترل‌های آیکونی نام دسترس‌پذیر فارسی داشته باشند.
- RTL واقعی با ویژگی‌های منطقی CSS؛ پشتیبانی LTR برای زبان‌های انتخاب‌شده.
- هیچ overflow افقی ناخواسته‌ای در موبایل مجاز نیست.

## 8. مرز تغییرات

این بازطراحی صرفاً محدود به ظاهر نیست، اما نباید رفتار محصول را خراب کند:

- حفظ همهٔ routeها، APIها، مدل‌های داده، مجوزها، نقش‌ها، منوها و ماژول‌ها.
- حفظ تمام ماژول‌های فعلی و ماژول‌های طراحی‌شده؛ هیچ موردی به‌خاطر ساده‌سازی UI حذف نشود.
- حفظ احراز هویت، منطق فرم‌ها، فیلترها، خروجی‌ها، اعلان‌ها و جریان‌های کاری.
- تغییر ساختار بصری componentها مجاز است؛ تغییر قراردادهای داده و منطق دسترسی بدون نیاز و تست مجاز نیست.
- هر مرحله باید قابل بازبینی و قابل بازگشت باشد.

## 9. Definition of Done

1. هیچ رنگ Meta وارد نشده و پالت فعلی بهار ثابت مانده است.
2. صفحه در عرض ۳۶۰px بدون سرریز افقی کار می‌کند.
3. RTL، ارقام فارسی، تاریخ جلالی و زبان‌های دیگر سالم‌اند.
4. reduced-motion و تنظیمات دسترس‌پذیری رعایت می‌شوند.
5. هیچ route، منو، ماژول، قابلیت یا دسترسی حذف نشده است.
6. lint، typecheck و build موفق‌اند؛ خطاهای محیطی جداگانه گزارش می‌شوند.
